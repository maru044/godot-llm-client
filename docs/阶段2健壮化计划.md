## 二、增强点（只补缺失）

### 1. 错误码按「可重试 / 不可恢复」分类
**现状问题**：`[0,400,429,500,502,503]` 全部重试，但 `400`（参数/内容问题）几乎不可恢复，重试 5 次浪费 token 且无意义。

**改动**：
- **可重试（带退避）**：`0`（网络断）、`429`（限流）、`500/502/503`（服务器）
- **不可恢复（立即失败 + 明确提示）**：`400`、`401`（key 无效）、`404`（地址错）

### 2. 统一诊断出口 → UI 可见
**现状**：`EventBus.system_error_occurred` 已存在，但需确认 UI 已 connect 并显示为 Toast。
**改动**：确认 `UIShell` 的 `_on_system_error` 已接线，把错误变成用户可见的红色 Toast（带原因）。

### 3. History 清洗覆盖所有失败路径（衔接 F2 干净发送）
**现状**：`_cleanup_failed_round` 只在 `400 && loop>=3` 触发。
**改动**：在**所有不可恢复错误**以及**重试耗尽**后，都调用 `_cleanup_failed_round()`，确保下一次发送基于干净历史。

### 4. 状态锁逐分支核对复位
**改动**：遍历所有 `return` 分支，确认 `_is_requesting = false` 无一遗漏，避免请求失败后 UI 卡在"生成中"。

### 5.（可选）CoT 解析打印优化
**现状**：模型返回无 `<thinking>` 标签时，CoT 栏带上 prefill 残留。
**改动**：让 CoT/正文打印逻辑更健壮，不把 prefill 文本当 CoT 显示。仅影响日志观感，不影响功能。

## 四、验收

- 正常对话（ds-v4-flash）仍成功返回
- 401/404 → 立即失败，UI 显示"API Key 无效/地址不存在"，不盲目重试
- 429/500 → 重试后仍失败才停止，UI 有提示
- 失败后发送下一条 → 历史已净化，无脏数据
- 无"生成中"卡死
